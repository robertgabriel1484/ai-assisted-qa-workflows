# AI-Assisted QA Usage Guidelines

## Purpose

AI can support QA work by accelerating brainstorming, documentation, test design, and analysis. It should not replace human review, product context, or final quality judgment.

## Appropriate Uses

- Drafting test cases from clear requirements
- Identifying edge cases
- Improving bug report clarity
- Summarizing logs or test results
- Creating regression checklist drafts
- Generating open questions for Product or Engineering
- Reviewing requirements for ambiguity

## Inappropriate Uses

- Inventing test evidence
- Claiming unverified behavior
- Replacing actual test execution
- Making release decisions without human review
- Sharing sensitive, private, or restricted company data
- Treating AI output as automatically correct

## Human Review Checklist

Before using AI-generated QA output:

- Confirm it matches the actual requirement.
- Remove unsupported assumptions.
- Verify expected results with Product/Engineering.
- Confirm test data is realistic.
- Check for duplicate or low-value test cases.
- Prioritize based on risk and release scope.
- Execute tests manually or through automation before reporting results.
