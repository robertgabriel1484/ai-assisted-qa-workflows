# Human Review Checklist for AI-Generated QA Output

Use this checklist before accepting AI-assisted QA content.

## Requirement Review

- [ ] Requirement was understood correctly.
- [ ] Acceptance criteria are represented accurately.
- [ ] Open questions are clearly listed.
- [ ] No unsupported business rules were invented.

## Test Case Review

- [ ] Positive scenarios are covered.
- [ ] Negative scenarios are covered.
- [ ] Boundary/data cases are covered where relevant.
- [ ] Expected results are specific and verifiable.
- [ ] Test steps are executable.
- [ ] Priority reflects actual business risk.

## Bug Report Review

- [ ] Title is specific.
- [ ] Steps are reproducible.
- [ ] Expected and actual results are clear.
- [ ] Evidence is attached or requested.
- [ ] Severity and priority are reasonable.
- [ ] Impact is explained without exaggeration.

## Release / Regression Review

- [ ] Scope matches the change.
- [ ] High-risk workflows are included.
- [ ] Defect re-test coverage is included.
- [ ] Data/API/integration impact is considered.
- [ ] Go/No-Go risks are documented.
